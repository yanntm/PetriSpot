# Web report of a campaign: design

A single self-contained HTML page per campaign folder, generated by
`webreport.py` from the CSVs the collectors write, with the data embedded as
JSON and the interaction done in the browser. Nothing to serve: open the file.
It replaces `REPORT.md` as the thing to read; the markdown stays as the plain
text fallback and the source of the README conclusions.

## Borrowed from MCC-analysis

`~/git/MCC-analysis` renders pandas frames into DataTables
(`buildHTMLFromCSV.py`: jQuery + `jquery.dataTables` 1.13 from the
datatables CDN, one `<table id=...>` per frame, sorting, paging and a search
box for free) and draws its charts with Plotly (`plotly-latest.min.js`,
`buildHardnessPlots.py`). Pages are Jinja2 templates under `templates/`.
We take the same three pieces, DataTables for every table, Plotly for every
chart, a Jinja2 template for the page, and the CDN links as they are. What we
do not take: the multi-page site, the R side, the Venn pages; one campaign is
one page.

## The page

A header (campaign, build, timeout, cores, when generated) and one tab per
examination, the classic ones first, then the total ones. Controls sit at the
top of each tab and filter everything below them at once.

### A classic examination (RD, RC, RF, ...)

Controls: **family** (multi-select, `ResIsolation`, `Shield*`...), **status**
of the values (`ok`, `wrong`, `missed`, `none`, `bonus`), **run outcome**
(finished, at the wall, failure, truncated), **backing** (values a single
tool has, values ITS-Tools 2026 has), free text search on the instance name.

1. Headline tiles: known, answered, ok, wrong, missed, none, bonus, wall
   hours, walker hours; recomputed on the filtered set.
2. **Runs table** (DataTables): instance, family, duration, outcome,
   ok/missed/none/bonus, walker calls/solved/seconds, failure. Click a row to
   expand its formulas with oracle, answer, status, backing tools.
3. **Values table**: one row per formula, the `support.csv` join
   (who, dissent), filterable by status: the missed and wrong lists the
   markdown gives, but sortable and searchable.
4. **Contest board**: bar chart of correct values per tool with our bar, and
   the table of instances where a chosen tool (dropdown, default ITS-Tools)
   got more right than we did, with both times.
5. **Time plots**: duration histogram (log x) coloured by outcome; scatter
   of our duration against the contest ITS-Tools time per instance, one
   point per instance, hover for the name, the diagonal drawn.
6. **Baseline**: when a second folder is given, the per formula status
   changes table (was / now, both durations) with a sankey or a simple
   census strip (missed -> ok 8, ok -> missed 3).

### A total examination (QLA, SMA, UBA)

Controls: **family**, **outcome** (complete, incomplete at the wall,
incomplete early, failure), **walker reached** (yes / no), completion range
slider.

1. Headline tiles: atoms, answered, completion, runs complete / at the wall,
   witnessed / proved (or open bounds), engine census, wall and walker hours.
2. **Completion histogram** (Plotly, 20 bins) and **completion against wall
   time** scatter, one point per run, size by atoms, hover for the instance,
   colour by whether the walker was ever called.
3. **Closing curve**: for the selected runs, the quartile times t25..t100 as
   a step plot per run (log time), the knee against slope question in one
   picture; a click on a run in the table highlights its curve.
4. **Runs table**: instance, family, atoms, answered, completion, witnessed,
   proved, engine columns, t25..t100, walker calls/seconds, last activity,
   failure.
5. **Families table**: instances, complete, mean completion, unanswered
   atoms, wall hours; a click filters the runs table to the family.
6. **Engine share** stacked bar per family: initial / walk / smt / dd /
   other over the answered atoms.
7. **Consistency**: `totalcheck.csv` and `ubacheck.csv` when present,
   confirmed / undecided / contradiction counts, the contradictions listed.
8. **Baseline**: completion before and after per instance, a scatter with
   the diagonal.

## Implementation

`webreport.py FOLDER [--baseline FOLDER] [--raw raw-result-analysis.csv]
[-o campaign.html]`, python 3 with pandas and jinja2 as MCC-analysis uses
them; the tool board numbers come from `toolboard.py`, the tables and
families from the same functions `report.py` uses, moved into a shared module
so the two reports never disagree. The template `webreport.html.j2` holds
the layout and the JavaScript (tabs, filters, DataTables init, Plotly
traces); the data goes in as one JSON object per examination. Size: the RC
values table is 31 k rows, the totals 5 k runs; a JSON of a few MB, DataTables
handles it client side. The Plotly and DataTables libraries load from their
CDNs as in MCC-analysis, so the page needs the network once; if that is a
problem the two files can be inlined at generation time.

Kept under 500 lines by splitting: `webreport.py` (driver, data frames to
JSON), `webreport.html.j2` (layout), `webreport.js` (the browser side,
inlined into the page at generation).
